How I Work

이렇게 개발합니다

기능이 동작하는 데서 멈추지 않고, 여러 기능이 하나의 플레이 흐름으로 이어지도록 구조를 맞춥니다.

01

구조 설계

입력 · 판단 · 행동을 계층으로 나누고 공통 로직을 상위로 올려, 캐릭터 종류가 늘어도 실행 흐름을 재사용하도록 설계합니다.

02

원인 추적

증상이 아니라 호출 순서와 데이터 흐름을 따라가 원인을 특정하고, 확인 방법을 남겨 재현 가능하게 만듭니다.

03

선택과 검증

대안을 비교해 제약 조건에 맞는 방식을 고르고, 같은 조건에서 전후를 측정해 결과를 확인합니다.

About

좋아하는 게임의 전투가 어떻게 만들어지는지 궁금했습니다

소울라이크 게임의 패링, 회피, 피격 반응이 만드는 긴장감에서 시작해, 지금은 그 흐름을 직접 구현하고 개선하고 있습니다.

끝까지 원인을 추적하는 개발 태도

문제를 작은 단위로 나누어 확인하고, 실행 흐름과 데이터 구조를 함께 살피며 원인을 끝까지 추적합니다.

보스 패턴을 공략하듯 디버깅

셰이더 변경 뒤 쓰지 않는 데이터를 계속 바인딩하던 코드를 로그 분석으로 찾아 프레임 저하를 해소했습니다.

협업 흐름을 이어가는 책임감

팀원이 막힌 충돌 처리 문제를 함께 재현하고 조건을 나눠 원인을 좁혀, 프로젝트 흐름이 끊기지 않도록 도왔습니다.

플레이 흐름을 고려하는 클라이언트 개발자

입력, 상태 전환, 애니메이션, UI, 이펙트가 자연스럽게 이어지는지 확인하고, 안정성과 유지보수성을 함께 고려하겠습니다.

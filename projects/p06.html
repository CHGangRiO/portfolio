AI와 6일 만에 만든 분대 디펜스

1인 + AI(Claude) · 2026.11.17 – 2026.11.23 · 기획서 v1.0 → v1.5

게임
세로 화면 분대 디펜스. 분대를 끌어 움직이며 몬스터를 막고, 결과 재화로 새 캐릭터를 뽑아 강화합니다.
내 역할
기획, 규칙과 수치 결정, 플레이 테스트, AI 작업 지시와 검토, 병합·배포 판단
환경
Unity 6000.3 2D URP, C#, HLSL, Unity Gaming Services(Authentication, Cloud Save), WebGL, Python
규모
PR 10개 병합, 자동 테스트 134개, 스테이지 2개, 캐릭터 6종, 몬스터 행동 5종
브라우저에서 플레이 GitHub 저장소 PDF
Why

분대가 커질수록 강해지지만, 피하기는 어려워진다

아이템을 먹어 분대가 불어나는 만족감에 대가가 없다는 점을 보고, 성장의 대가를 조작 난이도로 돌려주고 싶었습니다.

분대 = 벽

몬스터는 분대에 막히고, 놓친 몬스터는 아래 방어선을 깎습니다. 분대가 넓을수록 많이 막지만 폭탄병·기마병 같은 패턴을 피하기 어렵습니다.

두 길의 선택

적 길을 막을지, 금색 보상 길로 가서 분대를 키울지 매 순간 고릅니다.

끝이 있는 판

스테이지 1은 120마리, 2는 160마리. 보스까지 전멸시켜야 클리어입니다. 결과 재화로 뽑기를 하고 기록은 계정에 저장됩니다.

AI Collaboration

AI는 만들고, 방향과 기준은 제가 정했습니다

착수 전 정한 규칙: 코드를 쓰기 전에 AI가 기능 구조를 설명하고 의도를 물은 뒤, 제가 허락해야 구현합니다.

흐름

한 기능이 도는 순서

  1. AI가 구조안(설계 문서 12개)과 확인 질문을 올림
  2. 제가 규칙과 수치를 정하고 승인
  3. AI가 develop 브랜치에 기능 단위로 커밋 (Feat / Fix / Chore 분리)
  4. AI가 제 PC의 Unity를 배치 모드로 원격 실행해 컴파일·테스트·씬 생성까지 확인
  5. 제가 직접 플레이하고 피드백 → 1로
  6. 만족하면 develop → main PR, 제가 검토 후 병합
AI에게 맡긴 것내가 정한 것
코드 구현, 테스트 작성, 씬·프리팹 코드 생성핵심 규칙 (공격 대상, 반올림 방향, 클리어 조건)
기획서에 없는 수치의 초안플레이 후 수치 조정 (판 길이, 몬스터 수, 보스 등장 시각)
버그 원인 분석, 선택지 제시어느 선택지로 갈지, 범위에 넣을지
빌드·배포 자동화배포처와 공개 시점 (병합 = 공개)
Cases

대표 사례

CASE 01

수치는 Excel에서만 고치게 한 데이터 파이프라인

문제

플레이 테스트로 수치를 자주 바꿀 텐데, 그때마다 코드나 인스펙터를 건드리면 사람과 AI 모두 느려집니다.

내가 정한 것

Excel로 편집, 저장하면 자동 반영 + 수동 메뉴, 코드 값은 영문이고 설명·UI만 한글.

선택

AI가 "행마다 SO" 대신 "CSV마다 표 SO 하나"를 제안했고, 파일 수와 관리 부담이 줄어 승인했습니다.

구현

CSV → JSON → ScriptableObject. 오류가 하나라도 있으면 아무것도 쓰지 않고, 검증 규칙은 필드 속성으로 선언, SO는 값만 교체해 씬 참조를 유지합니다.

결과

표가 6종에서 스테이지·패턴·뽑기·보상까지 늘어도 같은 파이프라인을 썼고, 긴 웨이브 데이터는 Python 생성기로 만들었습니다.

남은 한계

표 사이 참조는 ID 문자열이라 임포터 검사에 의존합니다.

CASE 02

직접 플레이해서 웨이브를 다섯 번 고친 과정

문제

처음 웨이브는 5분짜리 판에 아이템이 너무 많아 긴장감이 없었습니다.

비교 기준

장르 대표 게임 영상을 AI가 2초 간격으로 분석해 길 구조·보상 밀도·판 길이를 숫자로 비교했고, 그중 네 가지만 골라 참조했습니다.

선택

"보상이 37초에 하나인데 참고 게임은 2~3초에 하나"처럼 숫자로 말하니 결정이 빨라졌습니다. 적 길과 보상 길을 분리했습니다.

구현

시드 기반 스트림 생성, 보상 보장 규칙, 보스 예고 배너, 몬스터 행동 5종(막기·추격·공성·관통·자폭).

결과

판 80초/100초, 스테이지당 120/160마리, 보스 포함 전멸 = 클리어로 확정했습니다.

남은 한계

수치는 제 플레이 기준입니다. 다른 사람의 플레이 테스트가 다음 단계입니다.

CASE 03

AI의 답을 한 번 더 확인하는 검증 루프

문제

AI는 클라우드에서 일해 Unity 에디터를 실행할 수 없었습니다. 코드는 쓰지만 컴파일·플레이 확인은 사람 몫이었습니다.

선택

제 PC의 Unity를 배치 모드로 원격 실행하도록 허용하고, 씬도 코드로 생성해 에디터 수작업을 0으로 만들었습니다.

잡은 문제 1

AI가 기억에 의존한 Light2D 어셈블리 이름이 URP 17.3에서 바뀌어 컴파일 에러. PR 전에 잡았습니다.

잡은 문제 2

씬 생성 순서 때문에 데이터 참조가 빈 채로 저장됨. "생성 성공"이 아니라 핵심 참조까지 검사하도록 빌더를 고쳤습니다.

결과

단위 테스트 32개 → 134개. 매 커밋 전부 통과한 뒤에만 플레이 테스트로 넘어갔습니다.

배운 점

눈에 보이는 버그(조준, 등장 위치)는 테스트가 아니라 제 플레이에서 나왔습니다. 역할을 나눠 맡는 게 맞았습니다.

CASE 04

처음 쓰는 UGS로 1시간 만에 계정 기록

문제

"웹에서 기록이 다른 사람과 공유되나?"를 확인해 보니 기록이 브라우저마다 따로 저장되고 있었습니다.

선택

AI가 낸 선택지 3개(안내만 / 기록 코드 / 로그인 + 클라우드 저장) 중 로그인을 골랐고, 무료 범위와 제출 일정을 조건으로 걸었습니다.

구현

Authentication(ID·비밀번호) + Cloud Save, 게스트 플레이, 게스트 기록을 새 계정으로 이동.

내가 한 일

UGS 대시보드에서 로그인 공급자 추가와 Cloud Save 활성화.

검증

릴리스 WebGL에서 가입, 중복 ID, 브라우저 저장소를 지운 뒤 클라우드에서 기록 복원까지 확인했습니다.

남은 한계

재화·뽑기 계산이 클라이언트에 있어 조작 방어는 없습니다. Cloud Code로 옮길 계획입니다.
